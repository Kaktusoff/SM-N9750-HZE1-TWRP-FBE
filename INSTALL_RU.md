# Установка со стоковой HZE1

## 1. Перед началом

Инструкция предназначена только для `SM-N9750` на `N9750ZSU6HZE1`.
Разблокировка загрузчика выполняет factory reset и необратимо сжигает Knox.
Зарядите телефон, сохраните все данные и заранее скачайте полную стоковую HZE1
для аварийного возврата.

Для Linux опубликован защищённый установщик Heimdall. Для Windows опубликованы
готовые Odin-пакеты `AP_*.tar.md5`. В них находятся те же проверенные на
телефоне BOOT и RECOVERY; упаковка, MD5-футер, LZ4-потоки и результат распаковки
проверяются автоматически. Сам путь передачи через Windows/Odin отдельно на
телефоне пока не перепрошивался, поэтому не пропускайте проверку модели, базы и
SHA-256.

## 2. Разблокировка загрузчика

Раздел можно пропустить, если Download Mode уже показывает разблокированный
загрузчик.

1. В Android включите параметры разработчика и **OEM-разблокировку**.
2. Полностью выключите телефон.
3. Зажмите обе клавиши громкости и подключите USB к компьютеру.
4. На экране Samsung выполните указанное долгое нажатие Volume Up и подтвердите
   разблокировку. Телефон сотрёт данные.
5. Пройдите первоначальную настройку Android, подключитесь к Интернету, снова
   включите параметры разработчика и убедитесь, что OEM-разблокировка уже
   активна.

Нельзя блокировать загрузчик при установленных custom BOOT или RECOVERY.

## 3. Проверка файлов

Распакуйте релиз. В Linux в каталоге с образами выполните:

```bash
sha256sum -c SHA256SUMS
```

Все строки должны получить статус `OK`. Пока Android загружен, дополнительно
проверьте модель и прошивку. Для этих ADB-команд и последующей миграции manager
нужны актуальные Android Platform Tools, временно включённая USB-отладка,
разблокированный экран и подтверждённый RSA-ключ компьютера; самой прошивке Odin
это не требуется:

```bash
adb shell getprop ro.product.model
adb shell getprop ro.build.version.incremental
```

Ожидаются `SM-N9750` и `N9750ZSU6HZE1`.

В Windows откройте PowerShell в каталоге с Odin-файлами и выполните:

```powershell
Get-FileHash .\AP_SM-N9750_HZE1_TWRP-Magisk-Alpha_v1.0.1.tar.md5 -Algorithm SHA256
Get-FileHash .\AP_SM-N9750_HZE1_TWRP-only_v1.0.1.tar.md5 -Algorithm SHA256
```

Сравните результаты с `SHA256SUMS-ODIN.txt`, приложенным рядом с архивами.

```text
aa12bed3104f48bdea7e7b18a26b72efe3f249237fbc18fdbfad9a483ec1cbd2  AP_SM-N9750_HZE1_TWRP-Magisk-Alpha_v1.0.1.tar.md5
363f8272d86450017ae7488f9f5c28976bbfc664886159de1040339200bd4206  AP_SM-N9750_HZE1_TWRP-only_v1.0.1.tar.md5
```

## 4. Выбор режима прошивки

Ни один из режимов ниже не форматирует и не прошивает `USERDATA`. Установка без
потери данных возможна только тогда, когда Download Mode уже показывает
разблокированный загрузчик. Первая разблокировка загрузчика Samsung всегда
выполняет factory reset; этот комплект не может отменить такое стирание.

Для постоянного TWRP и обычной загрузки Android с Magisk Alpha используйте:

```bash
./flash-heimdall.sh --flash-no-wipe
```

Команда прошивает только `BOOT` и `RECOVERY`; существующие данные Android на
точной базе HZE1 сохраняются. Старый параметр `--flash` остаётся псевдонимом
этого режима.

В Windows этому режиму соответствует Odin-файл:

```text
AP_SM-N9750_HZE1_TWRP-Magisk-Alpha_v1.0.1.tar.md5
```

Чтобы установить только TWRP, не меняя `BOOT` и пользовательские данные:

```bash
./flash-heimdall.sh --twrp-only-no-wipe
```

Режим только RECOVERY удобен для проверки или доступа к уже зашифрованным
данным. Если BOOT остаётся полностью стоковым, Samsung может восстановить
стоковый recovery после следующей обычной загрузки Android. Для постоянного
TWRP используйте связанный режим BOOT+RECOVERY выше.

В Windows режиму только RECOVERY соответствует:

```text
AP_SM-N9750_HZE1_TWRP-only_v1.0.1.tar.md5
```

## 5. Прошивка из Linux через Heimdall

Переведите телефон в Download Mode, подключите USB и проверьте соединение:

```bash
heimdall detect
```

Запустите защищённый скрипт из комплекта:

```bash
./flash-heimdall.sh --flash-no-wipe
```

Либо выполните точную команду вручную:

```bash
heimdall flash \
  --BOOT SM-N9750-HZE1-Magisk-Alpha-30700-BOOT-v1.0.1.img \
  --RECOVERY SM-N9750-HZE1-TWRP-3.7.1_12-FBE-v1.0.1.img \
  --no-reboot
```

После сообщения об успехе удерживайте Volume Down + Side/Power до погасания
экрана, затем сразу переключитесь на Volume Up + Side/Power, не отключая USB.
Отпустите клавиши после появления TWRP.

## 6. Прошивка из Windows через Odin

1. Установите Samsung USB Driver и распакуйте Odin `3.14.4`. Запускайте Odin
   обычным способом; режим совместимости и запуск от администратора обычно не
   нужны.
2. Закройте Smart Switch, Kies и другие программы, которые могут занять
   USB-порт. Используйте исправный кабель и прямой USB-порт компьютера без хаба.
3. Переведите телефон в Download Mode: выключите его, зажмите обе клавиши
   громкости, подключите USB и подтвердите вход клавишей Volume Up.
4. Убедитесь, что Odin показал активный порт `ID:COM` и строку `Added!!`.
5. Нажмите **AP** и выберите ровно один файл:

   - `AP_SM-N9750_HZE1_TWRP-Magisk-Alpha_v1.0.1.tar.md5` — постоянный TWRP + Magisk Alpha;
   - `AP_SM-N9750_HZE1_TWRP-only_v1.0.1.tar.md5` — только TWRP.

6. Поля **BL**, **CP**, **CSC** и **USERDATA** оставьте пустыми. Вкладка
   **Options**: снимите **Auto Reboot**; оставьте **F. Reset Time**; не включайте
   **Re-Partition**, **Nand Erase All**, **Flash Lock** или **DeviceInfo**. PIT не
   выбирайте.
7. Нажмите **Start** и не отключайте кабель. Продолжайте только после зелёного
   `PASS!`. При `FAIL!` сохраните Log Odin и не повторяйте прошивку вслепую.
8. После `PASS!` удерживайте Volume Down + Side/Power до погасания экрана и
   сразу переключитесь на Volume Up + Side/Power, не отключая USB. Отпустите
   клавиши после появления TWRP.

Odin прошивает только записи `boot` и/или `recovery` из выбранного AP-архива.
В пакетах нет `userdata`, `super`, `vbmeta`, PIT, CSC или модема. Поэтому при уже
разблокированном загрузчике и точной HZE1 данные не стираются. Первая
разблокировка загрузчика по-прежнему всегда выполняет factory reset.

## 7. Первый запуск TWRP

1. Проверьте версию `3.7.1_12-HZE1-FBE-lab-13`.
2. Введите тот же PIN или пароль, которым разблокируется Android.
3. Убедитесь, что внутренняя память показывает нормальные имена каталогов и
   размеры файлов.
4. Не форматируйте `/data`. Ошибка расшифровки на точной HZE1 — повод снять
   журнал, а не стирать данные.
5. Выберите **Reboot > System**.

Android должен загрузиться обычным нажатием Power. Модифицированный BOOT на
этапе early-init останавливает Samsung-службу `vendor_flash_recovery`, поэтому
стоковый recovery больше не восстанавливается поверх TWRP.

Если выбран режим только RECOVERY, пункт **Reboot > System** не добавит root, а
стоковый BOOT может восстановить стоковый recovery. Следующие шаги относятся к
связанному режиму BOOT+RECOVERY.

## 8. Приложение Magisk Alpha

Установите точный APK, приложенный к v1.0.1:

```bash
adb install root-tools/Magisk-Alpha-e8a58776-30700.apk
```

В приложении и команде `adb shell su -c 'magisk -v'` должны отображаться
`e8a58776-alpha` и рабочий root.

При обновлении с первоначально опубликованного v1.0.1 после запуска Alpha и
подтверждения root удалите **только APK старого официального manager 30.7**.
Пакеты двух manager различаются, поэтому иначе они остаются рядом:

```bash
adb shell pm path com.topjohnwu.magisk
adb uninstall com.topjohnwu.magisk
```

Если старый manager был скрыт под случайным пакетом, сначала используйте в нём
**Восстановить приложение Magisk** либо удалите точно определённое старое
приложение через его карточку Android. Не угадывайте случайный пакет и не
выбирайте **Удалить Magisk/полное удаление**: root находится в патченом BOOT и
должен сохраниться. Удаление только `com.topjohnwu.magisk` не удаляет Alpha-root
или модули.

Теперь выполните в Alpha **Скрыть приложение Magisk** с новым нейтральным
случайным пакетом manager. Используйте встроенный Zygisk Magisk и
**Enforce DenyList**; Zygisk Next и Shamiko в эталонном bank-first профиле
оставьте отключёнными. Не ставьте поверх официальный manager 30.7: он
относится к первоначальному снятому BOOT.
Рабочий банковский профиль и порядок модулей описаны в
[POST_INSTALL_ROOT_RU.md](POST_INSTALL_ROOT_RU.md).

## 9. T‑Банк после использования TWRP

TWRP может создать в общей памяти каталог `/sdcard/TWRP`. T‑Банк `8.2.2`
считает даже пустой каталог признаком модифицированной среды: T‑Pay может
оставаться рабочим, но вход по отпечатку исчезает. После выхода из recovery и
до запуска банка выполните:

```bash
./scripts/fix-tbank-biometric.sh
```

или в Windows PowerShell:

```powershell
.\scripts\fix-tbank-biometric.ps1
```

Перед запуском помощника установите актуальные Android Platform Tools. Для
самой прошивки Odin отладка по USB не нужна, но для помощника нужна: загрузите
Android, временно включите отладку, подключите и разблокируйте телефон,
подтвердите RSA-ключ компьютера и убедитесь, что `adb devices` показывает ровно
одно устройство со статусом `device`, а не `unauthorized`. Если политика
PowerShell блокирует скрипт, запустите его один раз без изменения системной
политики:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\fix-tbank-biometric.ps1
```

Помощник использует ADB без root, останавливает только T‑Банк и переносит весь
каталог под уникальным именем в `/sdcard/RecoveryBackups`. Он ничего не удаляет
и не перезаписывает. Данные T‑Банка очищать и приложение переустанавливать не
нужно. Полное объяснение приведено в
[POST_INSTALL_ROOT_RU.md](POST_INSTALL_ROOT_RU.md).

## 10. Вход в TWRP в дальнейшем

Выключите телефон, оставьте USB подключённым и удерживайте Volume Up +
Side/Power до появления TWRP.

## 11. Возврат на сток

Самый надёжный откат — прошивка полной точной стоковой
`N9750ZSU6HZE1`. Прошивка только стокового BOOT уберёт root, но при следующей
загрузке стоковая vendor-служба также восстановит стоковый recovery.

Блокировать загрузчик разрешается только после полного возврата всех разделов
на сток и успешной проверки загрузки. Повторная блокировка снова стирает данные,
а Knox уже не восстановится.
